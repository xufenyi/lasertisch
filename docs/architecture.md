## 总体数据流

```text
用户操作
  ↓
React 组件与 Fabric.js 画布
  ↓
Zustand 中的规范项目文档
  ↓  规划请求（项目快照 + 文档修订号）
Python 应用边界与 Pydantic 校验
  ↓
Shapely 几何转换 → CAM 路径规划
  ↓
设备无关 ToolpathPlan
  ↓
CSV 或 DBD 编码 → 原生保存对话框
```

前端状态中的 `EditorDocument` 与后端的 `ProjectDocument` 是同一份版本 2 项目契约，打开时兼容迁移版本 1。桥接 API 仍为版本 1，与项目格式版本独立。Fabric.js 对象和 Shapely 几何只是显示或计算投影，不能作为项目持久化来源。

## 坐标、单位与角度

- 世界坐标单位为整数微米，`1000 μm = 1 mm`。项目文件内部只保存整数，界面边界再与毫米文本互换。
- 工作区宽、高都必须大于 0 且不超过 `190000 μm`。工作区中心可以位于任意世界坐标，因而允许负坐标。
- 所有图形必须完整落在当前工作区中。旋转矩形以自身中心旋转，并以旋转后的四个角检查边界。
- 矩形由中心点、宽、高和角度描述；线段由有方向的起点与终点描述。
- 椭圆的 `kind` 为 `ellipse`，保存 `center`、`widthUm`、`heightUm`、`rotationTenthsDeg` 和 `sides`。边数为 3–1024 的整数，默认 64；尺寸必须为正且不超过工作区最大尺寸约束。项目中不保存曲线或冗余生成顶点。
- 多边形由局部顶点、局部原点的世界位置 `position` 和旋转角度描述。`parts` 中每个分离部分包含一个 `outerRing` 和零个或多个 `holes`。环隐式闭合，不重复保存首点。
- 多边形仅包含直线段。环不得自交、退化或有相邻重复顶点；同一部分的环边界必须互不接触，孔洞必须位于外环内部。分离部分不得重叠，共享单点可接受；孔洞中允许存在其他分离部分。
- 多边形宽高由旋转前的局部包围盒计算，不保存重复的尺寸或缩放状态；修改尺寸时同时缩放外环和孔洞的局部顶点。旋转与平移不改写局部顶点。
- 多边形加工、边界检查和统计使用同一组世界顶点：先按顺时针角度旋转，再按最近整数微米量化（半整数向正无穷舍入），最后加上整数位置。前后端必须采用相同规则，并检查量化后是否发生退化。
- 用户角度以顺时针为正，保存为 0.1° 的整数，并归一化到 `[0, 3600)`。
- Shapely 采用毫米浮点坐标；转换结果会量化回微米网格，防止计算噪声进入规范文档或设备路径。

### 椭圆生成与转换

椭圆按等参数角采样：从局部 +X 轴开始，第 i 个顶点角度为 `2πi/sides`，局部坐标为 `widthUm/2*cos(angle)`、`heightUm/2*sin(angle)`，并按最近整数微米量化。采样时用 `1e-7 μm` 容差消除半整数附近的三角函数浮点噪声，保持前后端结果一致；放置到世界坐标时沿用多边形规则。`fixtures/ellipse-sampling.json` 记录两端共享的局部及世界坐标摘要。

画布预览、最终显示、有效性校验、加工和转换为普通多边形都使用这套直线段生成规则。很小的尺寸与过高边数组合可能在微米网格上退化，必须拒绝，不可默默减少顶点或改变边数。工作区边界检查使用实际生成的多边形，不用生成矩形代替。

宽高是生成椭圆的矩形尺寸。低边数（如 3、5）不一定在四个方向都有极值顶点，因此控制框始终使用生成矩形的中心、尺寸和角度，不能从多边形包围盒反推参数。修改边数或尺寸时重新采样，不能在旧顶点上追加细分或累积缩放误差。

转换为普通多边形时，保留对象 ID、名称、加工参数、放置和加工顺序，将当前局部顶点写入 `parts`，形成一次可撤销操作。转换后通过多边形顶点编辑修改形状，不再提供椭圆边数控件。

最短轮廓边长仅用于提示；短于 0.1 mm 的轮廓边仍保留。填充的 100 μm 过滤规则不应用到椭圆轮廓上。`fixtures/ellipses-v2.lasertisch.json` 提供椭圆、正圆及低/高边数示例。椭圆仅接受版本 2 项目，版本 1 迁移不会将未知椭圆数据当作旧格式解释。

## 项目文档

项目文件使用 UTF-8 JSON，扩展名为 `.lasertisch.json`，当前 `schemaVersion` 为 `2`。主要字段包括：

- `workArea`：尺寸、中心和中心原点语义。
- `grid`：显示、间距、移动吸附和缩放吸附。
- `defaultProcess`：新建对象使用的加工参数。
- `globalSettings`：空行程速度、最短加工线段和原点起跳约束。
- `entities`：图形及其加工参数。
- `processingOrder`：包含每个对象标识且不重复的完整顺序。

对象的显示与锁定状态不属于项目文档。它们只保存在当前前端工作区，以对象 ID 关联；保存项目时不会输出，打开项目时全部恢复为显示、解锁。导入旧文件时允许存在 `visible`、`locked` 字段，但忽略其值。

实体类型包括 `line`、`rectangle`、`polygon`、`ellipse` 和 `text`。文字保存来源参数、固定 `parts`、生成器与引擎版本；重新生成或转换的规则见[文字管线](text-pipeline.md)。

打开项目时必须完整解析和校验，不能把未知或越界数据直接送入画布。保存时以规范文档为准，不序列化 Fabric.js 内部状态。

版本 1 的矩形和线段几何保持不变；版本 1 多边形的世界坐标顶点迁移为以其包围盒中心附近的整数点为原点的局部顶点，位置设为该原点、旋转角度设为 0，保持每个世界顶点不变。迁移不修改输入文件，后续保存统一写入版本 2；旧版软件不能读取版本 2；较早的版本 2 程序也可能不认识新增的文字类型。`fixtures/polygons-v2.lasertisch.json` 提供普通、凹形、带孔和多个分离部分的验收示例。

## 编辑器状态

编辑器把一次有意义的文档修改记录为一个历史快照。画布拖动期间可以连续显示数值，但一次拖动只应形成一次可撤销操作。属性输入在有效时提交；切换选择时不需要额外的“应用”动作。

`entityWorkspaceStates` 独立保存每个对象的显示与锁定状态。切换它们不修改规范文档、不增加 `documentRevision`、不改变脏状态，也不进入撤销与重做；新建或打开项目时清空。文档撤销、重做临时移除再恢复同一对象 ID 时，当前工作区状态继续保留。

加工顺序拖动在界面中先使用临时落点，松开后一次性提交新的 `processingOrder`，因此一次拖动只形成一条文档历史。取消或原位放下不提交。

每次文档变化都会增加 `documentRevision`。路径响应必须同时匹配请求标识和修订号；旧响应不能覆盖新文档。路径预览默认关闭，导出时如果没有当前修订号对应的缓存路径，则先执行一次规划。

### 复制、粘贴与重复

- `clipboard` 保存所选规范实体的深复制快照、相对加工顺序、来源文档 ID，以及复制时的工作区显示与锁定状态，只属于当前前端运行实例，不进入项目文档、保存文件或系统剪贴板。新建和打开项目保留剪贴板，应用重启后清空。
- `placementSession` 保存使用新 UUID 的模板实体、整体世界坐标包围框中心、候选实体、候选加工顺序、文档修订号及合法状态。粘贴从剪贴板建立会话；重复直接从当前选择建立，不覆盖剪贴板。
- 画布将同一整数微米偏移应用到组内所有实体。开启移动吸附时，组包围框中心沿用多选移动的半网格吸附规则；相对位置、旋转、局部顶点、文字来源和加工参数不变。同一文档内粘贴或重复保留工作区状态，跨文档粘贴的新对象默认显示并解锁。
- 候选实体是非交互式临时投影，不增加历史、修订号或加工重规划。合法候选显示为绿色，越界候选显示为红色；非法单击保持会话，Esc、工具切换、选择变化或文档变化取消会话。
- 放置提交前重新校验全部实体、工作区边界、ID 唯一性和完整加工顺序。成功时将整组追加到几何列表与固定加工顺序末尾，并作为一次原子历史提交选中新对象；不能发生部分创建。

### 多边形绘制与顶点编辑

- `polygonDraft` 是未闭合的世界坐标点列，`polygonEdit` 记录正在编辑的对象以及部分、轮廓和顶点索引。两者属于临时编辑状态，不进入项目文档或历史快照。
- 多边形工具逐点添加顶点，点击首点或 Enter 尝试闭合；Backspace 或撤销退回草稿上一点，Esc 或切换工具取消草稿。无效闭合保留草稿供修正，成功闭合后建立局部坐标、沿用默认加工参数，并只提交一次历史。
- 顶点编辑期间，Fabric 对象的整体变换和框选暂停；单独的交互叠加层显示所有外环、孔洞和分离部分的顶点。顶点选择和边命中的容差使用屏幕像素，不随缩放改变。
- 顶点拖动从起始快照计算候选几何，移动吸附作用于世界坐标，再逆变换为整数局部坐标；预览只写入 `transientEntities`，不触发加工重规划。松开时仅提交合法结果一次。无效结果、Esc、切换模式或文档修订变化会取消预览。
- 精确输入使用局部坐标，面板同时显示最终世界坐标。插入、删除和坐标修改都须通过同一套拓扑和工作区校验；不允许通过删除顶点移除整个环或对象，三顶点环不能继续删除。
- 双击边插入离鼠标最近的边上点；面板按钮在所选顶点之后的边上插入中点。闭合边、孔洞和多个分离部分使用相同规则。插入点会量化到整数局部坐标，退化时拒绝操作。
- Delete/Backspace 在顶点编辑模式只删除所选顶点，Esc 先退出顶点编辑并保留对象选择。输入控件仍优先处理文本编辑和 Enter 提交，不将输入中的删除按键交给画布。

## 布尔运算

布尔操作在前端只允许选择两个不同、当前可见且未锁定的闭合对象（矩形、多边形、椭圆或文字），不接受线段。显示与锁定是工作区状态，不发送到后端；请求包含规范项目快照、修订号、唯一请求标识、运算方式和有序的 A/B ID。`union`、`intersection` 和 `difference` 统一使用后端 Shapely，在 `0.001 mm` 网格上计算；减除始终为 A − B，椭圆使用当前边数生成的多边形，文字使用项目中保存的固定轮廓。

结果只保留有面积的 Polygon/MultiPolygon 部分。点或线接触不构成面积，因此可能返回明确的空结果。结果量化并规范排序后，将世界坐标环转换为局部整数顶点，以包围盒中心附近的整数点作为位置、旋转设为 0，并重复验证几何与工作区边界。保留孔洞和分离部分，不进行缓冲修复或擅自改变几何；如果相切环等情况违反现有多边形约束，应返回错误并保留输入。

`BooleanResponse` 成功时必须为一个普通多边形或 `empty=true` 且 `result=null`，失败时必须有错误且没有结果。前端验证请求标识、修订号、成功状态和完整多边形契约，不能直接接收未校验的结果。

`booleanPreview` 属于编辑器临时状态，不写入项目文件，不增加历史或文档修订号。画布将结果显示为绿色，A/B 淡化，暂时关闭整体拖动与框选；可缩放或使用中键平移。加工路径叠加暂时隐藏，原有预览开关保留。点击取消恢复原显示。

面板用异步请求标识及取消令牌隔离旧响应；状态提交时再次检查修订号、当前选择、工具状态、可编辑性和未完成拖动。文档修改、选择或工具变化、临时拖动、撤销/重做、打开新项目等都使旧预览失效。

应用运算是一次原子历史提交：默认删除 A/B，并在 A 的几何列表位置和固定加工顺序位置放入新结果，其他对象相对顺序不变。结果使用新 ID，名称由界面生成，完整继承 A 的加工参数。选择“保留原对象”时不更改原对象，将结果插在 A 后面；原对象仍按原参数加工，面板必须提醒可能重复加工。

空结果不能创建空多边形。替换模式下，用户需勾选确认后点击应用，才会移除 A/B，并记录一次可撤销操作；保留原对象模式下的空结果没有可应用内容。只预览或取消不改变项目。

`fixtures/booleans-v2.lasertisch.json` 为交互验收项目，包含重叠、孔洞、分离和椭圆四组对象；`fixtures/boolean-results.json` 供前端读取后端生成的规范结果进行契约与流程测试。

## 加工路径语义

### 顺序

- `processingOrder` 是强制顺序，规划器不得按距离重排对象。
- `none` 模式的对象跳过，其余对象按列表顺序各自产生一个任务。
- 线段严格从保存的起点加工到终点，不允许为了缩短空行程而翻转。
- 闭合轮廓遵循对象的顺时针或逆时针属性；每个环从离当前位置最近的现有顶点开始。

### 填充

- 扫描线以世界坐标原点和间距为基准，不随对象旋转。
- 0° 平行于世界坐标 X 轴，正角度为顺时针。
- 扫描线与边界或顶点相切时仍参与求交。
- 量化后的有效填充段长度不能小于 `100 μm`。该过滤仅适用于填充，轮廓边不会因为短于此长度而被删除。
- 相邻的非空扫描行使用往返方向，减少不必要的空行程。

### 运动段

`ToolpathPlan` 包含一个前导动作和按对象分组的连续运动段：

- 前导动作始终是从设备未知当前位置以激光关闭状态跳转到世界坐标 `(0, 0)`。
- `travel` 表示激光关闭的绝对移动。
- `contour`、`hatch` 和 `open_line` 表示激光开启的加工移动。
- 每个运动段的起点必须等于上一段终点，序号必须从 0 连续递增。
- 规划结束后不追加停靠动作，设备停留在最后一个目标点。

## 设备导出

`backend/src/lasertisch/device/exporter.py` 只接受已经校验的 `ToolpathPlan`，不依赖编辑器图形类型。每个前导动作或路径段映射为一条绝对运动命令：

- `jump`：从上一命令点到本命令目标点期间激光关闭。
- `mark`：从上一命令点到本命令目标点期间激光开启。

CSV 使用 UTF-8 文本，表头为 `command,x,y,speed`，坐标单位为毫米，速度单位为毫米每秒。DBD 使用小端二进制记录，包含设备参数、速度更新和绝对坐标命令；编码实现位于 `device/protocol.py`。软件只编码空行程速度和加工速度，不处理设备加速度或底层运动分辨率。

导出请求携带路径的输入修订号。修订号不一致、路径不连续、任务标识不匹配或序号断裂时，必须拒绝生成文件。

## 应用桥接与桌面外壳

应用边界暴露五个纯数据方法：

- `plan_toolpaths`：校验项目快照并返回设备无关路径。
- `export_device_program`：校验路径并返回 Base64 编码的 CSV 或 DBD 内容。
- `boolean_geometry`：校验项目与操作数，返回规范多边形或明确的空结果，不修改项目。
- `font_catalog`：返回随附默认字体和本机可用的单色轮廓字体身份。
- `text_outline`：返回单行文字来源与固定多边形快照，包含短边处理提示，不修改项目。

开发服务器中的接口与桥接对应如下，均使用 POST JSON。

| Vite 接口 | 标准输入输出脚本 | 应用方法 |
| --- | --- | --- |
| `/api/plan` | `plan_toolpaths_stdio.py` | `plan_toolpaths` |
| `/api/export` | `export_device_stdio.py` | `export_device_program` |
| `/api/boolean` | `boolean_geometry_stdio.py` | `boolean_geometry` |
| `/api/fonts` | `text_stdio.py fonts` | `font_catalog` |
| `/api/text-outline` | `text_stdio.py` | `text_outline` |

脚本位于 `backend/scripts/`。Vite 子进程设置 `PYTHONUTF8=1`，桥接明确使用 UTF-8，支持 Windows 下中文内容。

开发模式由 Vite 中间件启动短生命周期 Python 进程；桌面模式通过 pywebview 的 JavaScript API 调用同一应用边界。原生文件 API 负责：

- 打开不超过 20 MiB 的 UTF-8 项目文件。
- 以临时文件加原子替换方式保存项目文件。
- 解码并保存不超过 100 MiB 的 CSV 或 DBD 文件。
- 清理建议文件名中的 Windows 非法字符并补齐扩展名。

打包后的前端文件位于运行时资源目录 `web/`。桌面入口通过内置本地 HTTP 服务加载这些资源，并禁用普通网页下载，让文件写入统一经过原生保存对话框。

## 契约与测试

`schemas/` 是 Pydantic 模型导出的 JSON Schema，用来审查前后端契约是否同步。对应范围如下：

- `project-v2.schema.json`：当前项目文档；`project-v1.schema.json` 保留为旧版格式记录，不由当前模型覆盖。
- `plan-request-v1.schema.json`、`plan-response-v1.schema.json`：路径规划。
- `export-request-v1.schema.json`、`export-response-v1.schema.json`：设备导出。
- `boolean-request-v1.schema.json`、`boolean-response-v1.schema.json`：布尔计算请求和结果。
- `font-catalog-request-v1.schema.json`、`font-catalog-response-v1.schema.json`：字体目录。
- `text-outline-request-v1.schema.json`、`text-outline-response-v1.schema.json`、`text-outline-snapshot-v1.schema.json`：文字生成与独立轮廓快照。

Python 测试覆盖数据模型、单位、几何转换、轮廓、填充、规划、桥接、桌面文件 API、设备编码和语言包。前端测试覆盖单位与几何、项目文件、工具快捷键、Fabric.js 适配、路径渲染、状态历史、规划客户端和桌面桥接。

修改数据契约时，应同时更新 Pydantic 模型、TypeScript 类型与解析器、Schema 和两端测试。修改坐标或路径逻辑时，应优先补充整数微米边界、方向、相切、最短线段、顺序及连续性用例。
